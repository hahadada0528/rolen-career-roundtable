# 睿览 · 职业工作手册圆桌

作品集案例：多智能体桌面产品的 Mac 适配、品牌化看板与人在环流水线设计。

## 一句话

你说出一个职业，主 agent 点兵、分阶段推进背调、调研、知识库、分解与人机分工；每一步都等人批准，最后交出可复检的职业工作手册。

## 我解决什么问题

职业学习资料通常散落在招聘站、国家标准和个人笔记里。缺少一套「可批准、可复检、可沉淀」的流程：谁负责搜、谁负责核、什么时候该停下来等人拍板，都不清楚。

本项目把这件事做成固定席位的圆桌流水线：产出进本地知识库，关键必须能打开复检，关键门禁把人留在环内。

## 我做了什么

Windows 独立可执行包迁移为 macOS 可运行时：抽出应用字节码，用 Python 3.12 与原生依赖启动，并补齐桌面路径、数据目录与一键启动脚本。

看板品牌化：注入睿览 logo 与海军蓝视觉皮肤；顶栏、流程条、席位卡与对话区统一冷色纸面层级；桌面窗口标题同步品牌。

产品工程整理：作品集 README、安全忽略规则、公开仓库交付，去掉密钥与体积过大的 Windows 冻结包。

## 产品怎么跑

用户给出职业名后，知识库席搭建 Obsidian + LLM Wiki 骨架。

职业背调席给出求职网站参考；用户在看板「背调传送窗口」录入 JD；背调归纳后交给用户批准。

行业调研席检索岗位规范、验收与 KPI 类公开资料，交调研链接汇总；用户批准后，知识库席逐条核实入库。

用户上传素材，知识库全文蒸馏切片（每片带原文链接）。

分解席按第一性原理写目标分解，复检席核对结构，用户批准后进入人机分工。

人机分工席按工作事项写出：要学的工具、AI 可替代部分、必须人工部分；复检通过后由主 agent 终审交稿。

## 席位分工

主 agent：听懂意图、判定职业、点兵、等人批准、终审交稿。

知识库：本地职业知识库；切片带原文链接；整理上传资料。

职业背调：招聘信息职责归纳，去杂音而非词频统计。

行业调研：行业规范与岗位要求；只交 URL，不直接入库。

分解：第一性原理拆工作事项。

人机分工：工具学习 / AI 可替代 / 必须人工，需可复检引用。

复检：链接可达性与结构独立核验，默认倾向返工。

## 技术架构

桌面壳：pywebview（macOS WebKit），内嵌本地看板 board.html。

看板服务：本机 HTTP（默认 8765），负责对话、上传、背调录入与状态刷新。

运行时：RoundTable 协调各席；流水线状态写入 pipeline.json 与 workspace。

智能体：LangChain / LangGraph / Deep Agents；模型经 AGICTO OpenAI 兼容接口。

知识沉淀：每职业独立 data/{职业}/ 目录；知识库采用「compile, don't retrieve」的 LLM Wiki 模式。

## Mac 适配要点

从 PyInstaller onedir 包提取应用模块，避免在 macOS 上无法运行的 Windows 原生扩展。

入口 main.py 设置 CAREER_DESKTOP、AI_DATABASE_PATH、ROUNDTABLE_DATA_ROOT 等本机默认值。

board.py 在每次 write_board 后注入睿览皮肤，保证刷新看板后品牌不丢。

启动圆桌App.command 绑定 .venv，降低首次使用门槛。

## 技术栈

Python 3.12、LangChain、LangGraph、Deep Agents、pywebview、Obsidian / LLM Wiki 技能、AGICTO API。
